## 1. 行业背景与工作内容

### 1.1 什么是学科辅导

学科辅导（俗称「家教」「一对一」「上门辅导」）指教师或大学生针对 K12 学科（语数英、理化生、政史地等），在机构、学生家中或线上，进行**个性化、按课时计费**的教学服务。

与机构大班课不同，个人/小规模辅导的核心特征是：

| 维度 | 典型情况 |
|------|----------|
| 组织形态 | 个人老师、2–5 人小工作室，极少有专职教务 |
| 计费单位 | **按小时 / 按次**，单价因年级、科目、师资差异大 |
| 结算方式 | 先付课包、课后月结、按次现结并存 |
| 上课形式 | 1 对 1 为主；2–4 人拼课、寒暑假集训较常见 |
| 时间特点 | 周末/晚间集中；临近期末、中高考单价上浮；请假/调课/补课频繁 |
| 沟通对象 | 直接对接家长，费用核对常发生在微信 |

### 1.2 辅导老师的典型工作流程

```
招生/接单 → 试讲 → 约定单价与结算方式 → 固定排课
    ↓
每次上课：备课 → 授课（通常 1.5–2 小时/次）→ 简单反馈家长
    ↓
课后：记录本次课时 → 扣减课包 或 计入待结算账单
    ↓
周期末：汇总未收款 → 向家长确认 → 收款 → 归档
    ↓
续费/调价/停课/结课
```

### 1.3 课时费相关的业务细节（产品必须理解）

#### 计费模式

| 模式 | 说明 | 记录要点 |
|------|------|----------|
| **先付课包** | 家长一次购买 N 课时，上完扣减 | 剩余课时、每次扣减、续费节点 |
| **课后结算** | 按周/月汇总，课后或周期末付款 | 单次单价快照、未出账课时、账单状态 |
| **按次现结** | 当次上完当次付 | 收款确认、当日流水 |

#### 单价影响因素

- **学生年级**：小学 < 初中 < 高中，跨度可达 2–3 倍
- **科目难度**：竞赛/艺考/国际课程另议
- **师资身份**：大学生 50–100 元/h，专职/在职 150–300+ 元/h
- **时段溢价**：周末、寒暑假、临考冲刺常加价
- **拼课折扣**：2 人同价或各付拼课单价，与 1 对 1 价不同
- **附加费用**：远距离交通费、低于 2 小时单次上浮

#### 特殊课时类型

| 类型 | 常见处理 |
|------|----------|
| 试讲 | 免费 / 半价 / 全价，需单独标记 |
| 请假（学生） | 不计费或计半费，看约定 |
| 请假（老师） | 通常不计费，需补课 |
| 调课 | 改时间，不改变计费 |
| 补课 | 补之前缺的课，避免重复扣费 |
| 停课 | 暂停排课，保留剩余课包 |

#### 结算周期

- 周结（大学生家教常见）
- 月结（在职教师、长期稳定学生常见）
- 课包耗尽前续费（先付模式）

## 2. 用户画像与场景

### 2.1 目标用户（优先级排序）

| 优先级 | 用户 | 特征 | 核心诉求 |
|--------|------|------|----------|
| **P0** | 个人一对一老师 | 5–20 个学生，兼职或全职 | 快速记课、月底不错账、跟家长对账有依据 |
| **P0** | 大学生家教 | 学生少、单价低、周结为主 | 操作简单、记一笔不超过 10 秒 |
| **P1** | 拼课/小班老师 | 同一时段多学生、单价规则复杂 | 一次完成多人记课、各算各的账 |
| **P1** | 小工作室负责人 | 自己带课 + 代管 1–2 位老师 | 按学生/月份看收入汇总 |
| **P2** | 多科目/多年级老师 | 不同学生不同价 | 默认价 + 单次价覆盖 |

### 2.2 非目标用户（v1 不做）

- 中大型培训机构（需要排课、家校端、多教师权限，应使用 SaaS 教务系统）
- 艺体类培训（舞蹈、乐器课时逻辑差异大，v1 聚焦**学科**）
- 家长端（v1 仅服务老师，账单以导出/截图方式给家长）

### 2.3 典型使用场景

**场景 A：当晚 9 点刚下课**

> 李老师带完 2 小时高中数学，地铁上用手机记一笔：学生、时长、本次单价自动带出，标记「待月结」，10 秒完成。

**场景 B：月底对账**

> 王老师打开「待收款」，看到 3 位学生共 12 节课未结算，一键生成 11 月账单摘要，截图发家长微信群。

**场景 C：家长质疑剩余课时**

> 张同学家长说「还剩 8 节」，老师打开该生课包页，按时间倒序列出每次扣课记录，双方核对无误。

**场景 D：周六拼课**

> 同一时段带 A、B 两名初中生拼课，完成一次记课，系统自动按各自拼课单价分别入账。

## 3. 核心痛点分析

| 痛点 | 现状 | 后果 | 产品应对 |
|------|------|------|----------|
| **记课分散** | 微信聊天、备忘录、Excel 混用 | 漏记、重复记 | 统一入口，课后 10 秒记一笔 |
| **单价混乱** | 口头约定，事后记不清 | 算错金额 | 学生档案存默认价；单次记录存**价格快照** |
| **先付/后付混杂** | 不同学生规则不同 | 月结和扣课包逻辑打架 | 学生级别绑定计费模式，记课走不同分支 |
| **对账无凭据** | 只靠记忆或翻聊天记录 | 纠纷、信任损耗 | 可筛选、可导出的课时流水 |
| **拼课算账烦** | 手动按人头拆分 | 易错 | 一次记课，多人分拆 |
| **周期汇总慢** | 每月手工加总 | 拖延收款 | 按月/按生自动生成待收金额 |
| **换手机丢数据** | 本地表格无备份 | 历史全丢 | 本地数据库 + 可选 iCloud 同步 |

## 4. 产品概述

### 4.1 一句话定位

**课酬记（TutorLedger）** 是一款帮助学科辅导老师**准确记录课时、算清课酬、快速对账**的轻量工具。

Slogan 候选：**「下课记一笔，对账不扯皮」**

### 4.2 核心价值主张

| 用户痛点 | 课酬记 解决方案 |
|----------|-----------------|
| 记课麻烦、常忘记 | 首页「记课时」为一级入口，支持从课表快速完成 |
| 单价各不同、事后算错 | 学生档案维护默认价；每次记课保存**当次单价快照** |
| 先付课包 vs 月结混在一起 | 学生维度区分计费模式，记课后自动扣包或挂账 |
| 跟家长对账说不清 | 按学生/月份生成账单视图，支持导出摘要 |
| 工具太重、机构系统用不起 | 只做「学生 + 课时 + 钱」，不做家校 IM、不做复杂排课 |

### 4.3 设计原则

| 原则 | 说明 |
|------|------|
| **记课优先** | 打开 App 最快路径是「完成一节课并记费」 |
| **金额可追溯** | 任何一笔课酬都能追到：哪次课、什么单价、是否已收 |
| **规则在学生层** | 计费模式、默认单价绑定学生，减少每次重复选择 |
| **离线可用** | 地铁、地下室没网也能记 |
| **不做家长端** | v1 降低 scope；对账靠导出/截图 |
| **少即是多** | 不做机构级教务；排课仅服务于「提醒 + 快速记课」 |

### 4.4 已定稿的产品决策

| 议题 | 决策 | 理由 |
|------|------|------|
| 中文品牌名 | **课酬记** | 专业、直指课酬记账场景 |
| 工程名 | **TutorLedger** | 与现有 apps 英文工程命名一致 |
| 平台 | **仅 iOS** | 单人开发聚焦；与团队 SwiftUI 栈一致 |
| 最低系统 | **iOS 17+** | SwiftData、现代 SwiftUI |
| 团队 | **单人开发** | MVP 严格控制 scope，功能分期交付 |
| 数据存储 | **SwiftData 本地**；CloudKit 放 v1.1 | 先保证核心闭环，降低首版复杂度 |
| 联网 | **核心功能 100% 离线** | 上课场景网络不稳定 |
| 语言 | **简体中文**；英文 v1.2+ | 主力用户在国内 |
| 品类 | **仅学科辅导** | 聚焦 K12 语数英等，不扩艺体 |
| 账号 | **v1 无需登录** | 降低使用门槛；设备级数据 |
| MVP 拼课 | **不含**，v1.1 再加 | 单人首版优先单人记课闭环 |
| MVP 课表 | **仅备注型「下次时间」** | 完整周课表 v1.1 |
| Android | **不做** | 资源集中 iOS |

### 4.5 单人开发约束（影响排期与 scope）

| 约束 | 应对 |
|------|------|
| 无设计/后端/测试分工 | UI 复用 SwiftUI 系统组件，不做复杂自定义动效 |
| 并行能力有限 | 严格按 MVP 清单开发，新需求一律进 backlog |
| 首版不宜过大 | v1.0 目标 **5–8 周** 可上架的最小闭环 |
| 测试靠自测 + 小范围内测 | 核心路径：建学生 → 记课 → 出账 → 标记已收 |
| 运维为零 | 无自建服务器；数据本地 + 可选 iCloud |

## 5. 功能需求

### 5.1 功能架构总览

```
课酬记
├── 首页（今日/待办）
├── 记课时 ★核心
├── 学生
│   ├── 学生列表
│   └── 学生详情（概览 / 课时流水 / 账单 / 设置）
├── 账单与收款
├── 统计报表
└── 设置
```

### 5.2 学生管理

#### 5.2.1 新建学生

| 字段 | 必填 | 说明 |
|------|------|------|
| 姓名/昵称 | ✅ | 如「小明妈妈-初二数学」 |
| 年级 | 建议 | 小/初/高，影响默认单价参考 |
| 科目 | 建议 | 可多选 |
| 计费模式 | ✅ | 先付课包 / 课后结算 / 按次现结 |
| 默认单价（1 对 1） | ✅* | 课后结算、按次现结必填 |
| 拼课单价 | 可选 | 参与拼课时使用 |
| 课包总课时 | 先付必填 | 购课节数 |
| 结算周期 | 课后结算 | 周结 / 月结 |
| 备注 | 可选 | 上课地点、家长称呼、约定说明 |

#### 5.2.2 学生详情 — 四个 Tab

| Tab | 内容 |
|-----|------|
| **概览** | 剩余课包、待收金额、最近上课、下次计划（若有） |
| **课时** | 按时间倒序的课时流水，可编辑/作废 |
| **账单** | 按周期聚合的账单列表及收款状态 |
| **设置** | 修改单价、计费模式、停课/结课 |

#### 5.2.3 学生状态

- **在读**：正常记课
- **停课**：不删数据，不再出现在默认记课列表
- **结课**：归档，不参与统计

### 5.3 记课时（核心功能）

#### 5.3.1 记课入口

1. 首页 FAB「记课时」
2. 学生详情页「记一笔」
3. （P1）课表点击已结束课程 → 快速完成

#### 5.3.2 记课表单

| 字段 | 必填 | 默认/规则 |
|------|------|-----------|
| 学生 | ✅ | 多选则进入拼课模式 |
| 上课日期 | ✅ | 默认今天 |
| 开始/结束时间 或 时长 | ✅ | 默认 2 小时；支持 1.5h 等 |
| 科目 | 建议 | 继承学生主科目 |
| 本次单价 | ✅ | 默认取学生档案价，**可修改且仅影响本条** |
| 课时类型 | 可选 | 正常 / 试讲 / 补课 / 赠课 |
| 计费结果 | 自动 | 见下表 |
| 备注 | 可选 | 本次内容摘要 |

#### 5.3.3 记课后的系统自动处理

| 学生计费模式 | 保存后系统行为 |
|--------------|----------------|
| 先付课包 | 扣减 1（或自定义）课时；剩余不足时首页提醒续费 |
| 课后结算 | 产生「未出账课时记录」；金额 = 单价 × 时长 |
| 按次现结 | 产生「待收款」；可当场标记已收 |

#### 5.3.4 拼课记课

- 同一表单多选学生
- 每人按各自**拼课单价**（无则回退 1 对 1 价）分别生成记录
- 共享同一时段、同一科目

#### 5.3.5 编辑与作废

- **未出账 / 未扣课包** 前：可改单价、时长、日期
- **已出账 / 已收款**：仅允许「作废」并留痕，不物理删除
- 作废需填原因（记错、学生请假、重复录入等）

### 5.4 账单与收款

#### 5.4.1 待收款视图

- 按学生分组展示未收金额
- 筛选：本周 / 本月 / 全部
- 支持勾选多条课时 → **生成账单**

#### 5.4.2 账单

| 属性 | 说明 |
|------|------|
| 账期 | 如「2026 年 1 月」或自定义区间 |
| 包含课时 | 明细列表，可展开 |
| 合计金额 | 自动汇总 |
| 状态 | 待发送 / 已发送 / 已收款 |
| 收款日期 | 标记已收时记录 |
| 收款方式 | 微信 / 支付宝 / 现金 / 其他（可选） |

#### 5.4.3 账单分享（v1 轻量）

- 生成**文字摘要 + 明细**（适合复制到微信）
- （P1）生成图片账单卡片

#### 5.4.4 先付课包续费

- 记录「购课」：增加课包课时、可选记录实收金额
- 与「上课扣减」分开，形成课包流水

### 5.5 课表（P1，MVP 可简化）

MVP 可只做「下次上课时间」字段；完整课表放 P1。

| 能力 | 说明 |
|------|------|
| 固定课 | 每周六 14:00–16:00 |
| 临时课 | 单次安排 |
| 完成跳转 | 到点/课后从课表一键「记课时」 |
| 请假标记 | 该次不上，不计费 |

### 5.6 统计报表

#### 5.6.1 首页概览

- 今日/本周已上节数
- 本月已收 / 待收金额
- 课包不足学生数（≤3 节提醒）

#### 5.6.2 报表页（MVP 基础版）

| 报表 | 内容 |
|------|------|
| 月度收入 | 已收金额柱状/列表，按学生贡献排序 |
| 课时量 | 本月完成节数、总时长 |
| 学生排行 | 谁贡献收入最多 / 上课最多 |

### 5.7 设置

- 货币单位（默认 ¥）
- 默认课时时长（1.5h / 2h）
- iCloud 同步开关
- 数据导出（CSV）
- 外观（跟随系统）

## 6. 数据模型概要

```
Student（学生）
  ├── 基本信息：姓名、年级、科目、状态
  ├── 计费：模式、默认单价、拼课单价、结算周期
  ├── 课包：总课时、剩余课时（先付）
  └── 关系 → LessonRecord[], Bill[], PackageTransaction[]

LessonRecord（课时记录）★核心实体
  ├── studentId, date, duration, subject
  ├── unitPrice（快照）, amount（计算值）
  ├── type：normal | trial | makeup | free
  ├── billingStatus：deducted | pending | billed | paid | void
  └── note, groupSessionId（拼课关联）

Bill（账单）
  ├── studentId, periodStart, periodEnd
  ├── lessonRecordIds[], totalAmount
  ├── status：draft | sent | paid
  └── paidAt, paymentMethod

PackageTransaction（课包流水）
  ├── studentId, type：purchase | deduct | adjust
  ├── hours, amount（购课实收，可选）
  └── date, note
```

**关键设计：单价快照**

- `Student.defaultUnitPrice` 仅作默认值
- 每次 `LessonRecord.unitPrice` 在创建时复制保存
- 后续改学生默认价**不影响**历史记录

## 9. 竞品与差异化

| 产品 | 定位 | 优点 | 不足 | 我们的差异 |
|------|------|------|------|------------|
| 来记课 / AI教务 | 机构 SaaS | 功能全、家校端 | 贵、重、个人用不起 | **个人轻量、低价/免费** |
| 个人教培助手 | 个人老师 | 课表+账单+成绩 | 功能多，学习成本 | **聚焦课酬，记课更快** |
| Excel / 备忘录 | 手工 | 灵活 | 易错、难汇总 | **结构化 + 自动汇总** |
| 日历 App | 提醒 | 习惯成熟 | 无金额逻辑 | **日历 + 计费一体** |

**差异化一句话：不做「小机构教务系统」，做「个人老师口袋里的课酬账本」。**

## 12. 风险与待定决策

### 12.1 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 功能蔓延成「小教务系统」 | 工期失控、定位模糊 | 严格 MVP 清单；排课/成绩坚决后置 |
| 计费规则过于多样 | 开发复杂度爆炸 | v1 只支持三种主模式；特殊场景用备注 |
| 用户已有 Excel 习惯 | 迁移成本高 | 提供 CSV 导入模板（v1.1） |
| 与「个人教培助手」同质 | 获客难 | 强调「10 秒记课」「课酬账本」单点 |

### 12.2 剩余待定（不影响开工）

| 议题 | 选项 | 倾向 |
|------|------|------|
| 变现 | 免费 / 订阅 / 买断 | MVP **完全免费** 验证需求；v1.2 限学生数 Freemium |
| App 图标与视觉风格 | 待定 | 简洁工具风，偏账本/日历，避免「教务系统」感 |

## 附录 A：记课业务规则速查

| 场景 | 处理 |
|------|------|
| 先付学生上课 | 扣 1 节，写 PackageTransaction(deduct) |
| 先付剩余 ≤3 节 | 首页待办提醒「联系续费」 |
| 课后结算上课 | LessonRecord.status = pending，计入待收 |
| 按次现结上课 | pending → 用户点「已收」→ paid |
| 试讲免费 | type=trial，amount=0 |
| 试讲半价 | type=trial，单价手动减半 |
| 记错课 | 作废原记录，新建正确记录 |
| 修改学生默认价 | 仅影响后续新课，历史不变 |
